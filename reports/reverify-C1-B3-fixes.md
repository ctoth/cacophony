## Fix 1 - C1 loudness worklet LFE exclusion

VERDICT: CORRECT, with one provenance caveat.

1. INFO - 5.1 LFE is excluded in the current worklet path. `src/processors/loudness-meter.ts:52` defines a channel-count layout table, `src/processors/loudness-meter.ts:57` maps 6-channel input to `["L", "R", "C", "LFE", "Ls", "Rs"]`, and `src/processors/loudness-meter.ts:185` selects that layout from `this.channelCount`. The three loudness summation paths multiply by `CHANNEL_WEIGHTS[this.channelLabel(c)]` at `src/processors/loudness-meter.ts:193`, `src/processors/loudness-meter.ts:201`, and `src/processors/loudness-meter.ts:269`; `src/meters/loudness-core.ts:43` defines the weights and `src/meters/loudness-core.ts:49` makes `LFE` weight 0.

2. INFO - Stereo and 5.0 behavior are unchanged from the old default order. The old commit parent had only `DEFAULT_CHANNEL_ORDER = ["L", "R", "C", "Ls", "Rs"]` and `channelLabel()` returned that order with `"C"` fallback. The current `src/processors/loudness-meter.ts:53` maps 2-channel input to `["L", "R"]`, and `src/processors/loudness-meter.ts:56` maps 5-channel input to `["L", "R", "C", "Ls", "Rs"]`, matching the previous first-two and full-five behavior.

3. INFO - Mono still has weight 1.0. Current mono maps channel 0 to `"C"` at `src/processors/loudness-meter.ts:53`, and `src/meters/loudness-core.ts:46` gives `C` weight 1.0. The old mono label was `"L"`, also weight 1.0 at `src/meters/loudness-core.ts:44`, so the loudness value is unchanged.

4. INFO - `this.channelCount` is set before `channelLabel()` is reached in the process-driven paths. `process()` rejects empty input first, then calls `this.ensureChannels(input.length)` at `src/processors/loudness-meter.ts:283`. `ensureChannels()` assigns `this.channelCount = count` at `src/processors/loudness-meter.ts:153`. The later call sites for `channelLabel()` are in `loudnessOf`, `windowLoudness`, and `gatedLoudnessOfSet` at `src/processors/loudness-meter.ts:193`, `src/processors/loudness-meter.ts:201`, and `src/processors/loudness-meter.ts:269`.

5. INFO - Unsupported channel counts fall back sanely to the previous behavior. `src/processors/loudness-meter.ts:185` uses `CHANNEL_LAYOUTS[this.channelCount] ?? DEFAULT_CHANNEL_ORDER`, and `src/processors/loudness-meter.ts:186` falls back to `"C"` beyond the layout length. Counts 4, 7, 8, and other unsupported counts therefore keep the old `L/R/C/Ls/Rs` prefix plus center-weight fallback for extras.

6. LOW - The runtime 5.1 index order is correct for Web Audio, but BS.1770-5 is not the direct channel-index authority. BS.1770-5 page image `papers/itu-bs1770-5-loudness/pngs/page-004.png` says the loudness algorithm has five main measured inputs and excludes LFE; `papers/itu-bs1770-5-loudness/pngs/page-008.png` gives weights only for L/R/C/Ls/Rs. The W3C Web Audio 1.0 spec is the source that defines the 5.1 buffer order as index 0 front-left, 1 front-right, 2 front-center, 3 low-frequency, 4 back-left, 5 back-right. So the code's `["L", "R", "C", "LFE", "Ls", "Rs"]` mapping is right for the AudioWorklet input, but the in-code comment at `src/processors/loudness-meter.ts:45` over-attributes index order to BS.1770-5. This is not a behavioral regression.

## Fix 2 - B3 PGHI first-frame multi-component seeding

VERDICT: CORRECT, with a weak test.

1. INFO - The fix assigns every first-frame significant component instead of only the single global-max island. Significant bins are counted into `remaining` and marked in `inSet` at `src/processors/timestretch-core.ts:366` through `src/processors/timestretch-core.ts:377`. The first-frame branch loops while `remaining > 0` at `src/processors/timestretch-core.ts:397`, picks the max unassigned significant bin at `src/processors/timestretch-core.ts:400` through `src/processors/timestretch-core.ts:404`, assigns it at `src/processors/timestretch-core.ts:407` through `src/processors/timestretch-core.ts:410`, then drains frequency propagation at `src/processors/timestretch-core.ts:417` through `src/processors/timestretch-core.ts:431`.

2. INFO - The directional frequency-update formulas are unchanged from the parent implementation. The parent first-frame branch used `phiS[mh + 1] = phiS[mh] + ratio * dfFwd[n][mh]` and `phiS[mh - 1] = phiS[mh] - ratio * dfFwd[n][mh - 1]`; the current first-frame branch still uses those formulas at `src/processors/timestretch-core.ts:421` and `src/processors/timestretch-core.ts:427`. The code still documents the deliberate Algorithm 1 frequency-propagation deviation at `src/processors/timestretch-core.ts:276` through `src/processors/timestretch-core.ts:295`.

3. INFO - Single-island first-frame behavior is output-identical. The first outer iteration picks the same global max seed as the old code, then assigns the same connected significant neighbors using the same forward/backward formulas. The only mechanical difference is that the new inner loop at `src/processors/timestretch-core.ts:417` drains any already-assigned heap tail after `remaining` reaches 0; those extra pops do not write phase values because all neighbor writes are guarded by `!assigned`.

4. INFO - The fix matches Prusa 2022 Algorithm 1's assignment invariant. In `papers/Prusa_2022_PhaseVocoderDoneRight/pngs/page-002.png`, Algorithm 1 creates significant set `I`, loops while `I` is not empty, and removes assigned bins from `I` on the time and frequency propagation lines. The current first-frame branch now repeats seed-and-spread until `remaining` reaches 0, which is the implementation's equivalent of emptying `I`. The old branch could leave disconnected significant bins at their zero-initialized phase.

Termination analysis:

- Outer loop progress: `remaining` is initialized as the exact count of significant unassigned bins at `src/processors/timestretch-core.ts:366` through `src/processors/timestretch-core.ts:377`. Each successful outer iteration assigns one unassigned significant seed and decrements `remaining` at `src/processors/timestretch-core.ts:407` through `src/processors/timestretch-core.ts:410`. The inner loop may further decrement it. Therefore every normal outer iteration strictly decreases `remaining`.
- `seed < 0` guard: `src/processors/timestretch-core.ts:406` is unreachable under the maintained invariant that `remaining` equals the count of `inSet[m] && !assigned[m]`. It is still a correct safety guard against an invariant break because it prevents an infinite loop when `remaining` is stale and no unassigned significant bin exists.
- Inner heap drain: `src/processors/timestretch-core.ts:417` pops one heap item per iteration. The only pushes occur after marking a previously unassigned significant neighbor assigned at `src/processors/timestretch-core.ts:421` through `src/processors/timestretch-core.ts:424` and `src/processors/timestretch-core.ts:427` through `src/processors/timestretch-core.ts:430`. A bin can be pushed only once because assignment happens before push and every write is guarded by `!assigned`.
- No double assignment: the seed is marked assigned before it is pushed at `src/processors/timestretch-core.ts:407` through `src/processors/timestretch-core.ts:411`; both neighbor writes check `!assigned` before writing. Later heap pops can observe already-assigned neighbors but cannot write them again.
- Exact-once assignment: every significant bin is assigned either as a seed or as a propagated neighbor. Insignificant bins are assigned random phase before the branch at `src/processors/timestretch-core.ts:378` through `src/processors/timestretch-core.ts:381` and are excluded from propagation by `inSet`.

Test vacuity: the B3 test is honest but weak as a regression detector. Its comments explicitly say it is not a phase regression test and only claims termination, finite output, tone survival, and determinism at `src/processors/timestretch-core.test.ts:312` through `src/processors/timestretch-core.test.ts:321`. The assertions match that scope: finite output and length at `src/processors/timestretch-core.test.ts:333` through `src/processors/timestretch-core.test.ts:334`, tone-bin power checks at `src/processors/timestretch-core.test.ts:336` through `src/processors/timestretch-core.test.ts:341`, and deterministic equality at `src/processors/timestretch-core.test.ts:343`. It could pass on the old implementation because separated stationary tones can retain magnitude even when disconnected first-frame components get default zero phase. A tighter test can detect the fix by exposing first-frame assignment coverage through a test-only debug path or by using a broadband/gapped first-frame transient with an assertion on temporal concentration or phase-sensitive reconstruction, not just tone-bin magnitude.
